# Rangitoto 主动学习设计

## 背景

Rangitoto 全场双裁剪扫描已经产生 2,942 个合并候选，但这些候选不能作为 2,942 条人工待办。
它们来自同一个仅用 90 个窗口训练的 bootstrap checkpoint、0.4 秒滑窗和 0.2 低阈值扫描，
其中包含 823 个双视角同动作重复组和 495 个跨视角动作冲突组。候选置信度中位数为
`0.2929`，只有 2 条达到 `0.5`；动作又高度集中在 `set` 和 `attack`。

现有模型已经在 90 条训练记录上达到 100% 训练集成绩，但没有独立验证集。这说明继续增加训练轮数
不会解决新比赛上的泛化问题。人工逐行修正全量候选也会重复观看相邻滑窗和同一回合，无法以合理成本
建立训练集。

本设计把 2,942 条结果重新定义为可审计的候选池，并采用按短回合或连续时间块选择的主动学习流程。
用户每轮最多复核 40 个短片，一次播放并穷举片段内所有我方动作。完整候选 JSON、CSV 和 XLSX
继续保留，但不要求填写。

## 目标

- 每轮最多交付 40 个互不重复的短回合或连续时间块，不再把全量候选交给用户逐行处理。
- 每个短片优先为 10 至 20 秒；为保留完整动作序列可放宽到 5 至 30 秒，不在动作中间强制截断。
- 一次观看记录片段内全部我方动作，同时解决重叠候选、双视角重复、动作冲突和漏报。
- 人工只需确认到秒级；输入片段内相对秒数，程序换算为原视频绝对时间。
- 首轮预计从 40 个短片获得约 150 至 250 个动作或背景训练窗口；该数量是规划范围，不是强制验收值。
- 每一轮选择、人工结果、训练清单和模型版本都可重建、可校验且不覆盖上一轮。
- 主动学习批次只用于提高标注效率；泛化指标必须来自未参与训练的完整比赛。
- README 始终明确全量候选、主动学习样本和独立评估真值的区别。

## 非目标

- 不完成人工逐条复核 2,942 个候选。
- 当前不使用自动伪标签，也不把双裁剪一致当作两个独立模型的投票。
- 不在本阶段开始球员检测、号码归属、产品前端、账户、数据库或球员统计。
- 不承诺首版选择器能自动精确找到发球到死球的真实回合边界。
- 不把主动学习批次上的训练成绩或偏置抽样成绩称为产品准确率。

## 方案选择

### 采用：按短回合的主动学习

选择器按冲突、置信度、稀有动作、时间分布和背景区间挑选 40 个短片。人工观看一个短片后填写
其中全部我方动作；程序再将结果转换为训练窗口和硬负样本。该方案同时减少重复播放并发现模型漏报，
是当前数据量下人工收益最高的路径。

### 不采用：随机抽取完整回合

随机回合容易实现，也能估计整体分布，但在首轮会浪费较多时间观看模型已经会处理的简单片段，
稀有的 `receive`、`block` 和 `dig` 也可能继续缺样本。保留少量随机片段作为无偏对照，
不把它作为全部选择策略。

### 暂不采用：高置信度伪标签

当前 2,942 个候选中只有 2 条置信度达到 `0.5`，双视角又来自同一个 checkpoint，错误高度相关。
此时自动加入伪标签会放大 `set` 和 `attack` 偏置。只有某一动作在独立验证集上达到至少
`0.95` Precision、至少有 20 个正样本支持并经过随机抽查后，才允许单独讨论该类的降权伪标签。

## 复核单位

主动学习的人工单位是短片，不是候选行。每个短片包含：

- 稳定的 `round_id` 和 `clip_id`。
- 原视频仓库相对路径、内容哈希、绝对开始和结束时间。
- 可播放的低体积代理短片和原视频可读时间码。
- 只读候选提示，包括动作、置信度、far/near 来源、重复组、冲突组和选择原因。
- 人工动作列表：动作、片段内开始秒、片段内结束秒、我方所在裁剪和可选备注。

用户输入片段内的相对秒数，不需要从 109 分钟原视频中换算全局秒数。应用结果时，程序使用
`clip_start_seconds + relative_seconds` 生成原视频绝对时间，并同时保留原始相对输入用于审计。

人工动作非空即代表该短片已复核，不增加审核状态列或复选框。如果短片内没有我方动作，
填写一条 `background`；这同时明确表示该片段已经穷举检查，而不是遗漏填写。

首版只生成训练所需的我方标签。`receive` 仅指接对方发球，`dig` 仅指对方进攻后的防守起球；
`far` 和 `near` 只是裁剪位置，不代表固定球队。

## 首轮选择规则

首轮从已经验证的 `merged_candidates.json` 和两路完整窗口预测中确定性选择 40 个唯一短片。
选择按优先级排他执行，同一个短片可以记录多个选择标签，但只占一个名额：

1. **20 个冲突或稀有动作短片。** 优先覆盖全部 15 个 `receive`、`block`、`dig` 候选，
   再从不同 `conflict_group_id` 中补足；同一冲突组最多选择一个短片。
2. **8 个高置信度尾部短片。** 优先从置信度至少 `0.4` 的 `set`、`attack`、`serve` 中选择；
   不足时按置信度降序补足，专门发现模型最自信的误报并形成硬负样本。
3. **4 个双视角同意短片。** 从无冲突的同动作 duplicate groups 中选择，用于检查双裁剪一致
   是否真的更可靠。
4. **4 个随机候选短片。** 使用固定随机种子，从尚未入选的候选中按全场时间分层抽取，
   作为候选 Precision 的对照样本。
5. **4 个无候选时间块。** 从 far 和 near 都预测为 `background` 的区间按全场时间分层抽取，
   人工穷举其中所有动作，用于发现漏报。

如果某一桶无法提供足够的合法短片，选择器按上述顺序把空缺转给下一桶，并在批次摘要中记录
原计划、实际数量和转移原因。选择器不得重复同一 source event、duplicate group 或 conflict group
来凑数。

短片必须分布在至少 10 个等长比赛时间段中，并覆盖可用的 far/near 场景。两个入选锚点默认至少
相隔 5 秒；属于同一连续动作序列时合并为一次播放。首版根据候选时间和上下文生成短时间块，
不宣称自动识别了真实回合边界；人工可以用秒级输入修正动作时间，但不负责修复全部候选边界。

## 后续轮次

每一轮都使用累计人工标签重新训练并重扫未复核池，然后排除已经覆盖的时间块和来源组，再选择
下一批 40 个短片。默认最多先执行三轮；是否继续由新增样本收益和独立验证指标决定，不以清空
2,942 个历史候选为目标。

当前推理输出只保存 top-1 动作和置信度，首轮只能用跨裁剪冲突、top-1 置信度和时间分层作为
不确定性代理。下一轮推理格式应增加完整类别概率或至少 top-2 动作、top-2 置信度和 margin，
从第二轮开始按 margin 或 entropy 选择真正的决策边界样本。视觉 embedding 多样性可以后续加入，
但不是首轮必需条件。

## 人工结果到训练清单

应用人工结果时：

1. 校验 40 个短片的来源哈希、顺序、唯一性和时间边界。
2. 要求每个短片至少包含一个人工动作或显式 `background`。
3. 校验动作属于七类，时间为非负有限数，且落在短片范围内。
4. 将相对秒数转换为原视频绝对秒数，并保留秒级来源精度。
5. 合并同一真实动作覆盖的相邻候选，不要求为每条历史候选写一条人工决定。
6. 将确认动作写为正样本；将明确误报和动作保护区之外的抽样窗口写为 `background`。
7. 背景窗口使用固定随机种子生成，并设置每轮上限，避免背景数量淹没少数动作。
8. 输出新的累计清单，不覆盖美国队对德国队的 90 条来源清单或任何上一轮结果。

为避免动作边界附近被误采为背景，自动背景窗口不得与人工动作重叠，并在动作前后保留保护区。
默认在人工动作前后各保留 0.5 秒保护区，每轮自动生成的背景窗口不超过新增正动作数量。
两个默认值允许通过命令参数修改，但最终值必须写入批次结果，不能隐藏在脚本常量中。

## 训练策略

继续使用 Kinetics 预训练 R3D-18，不从零训练。当前实现直接微调整个骨干，在少量数据上容易
记忆训练集；主动学习版本采用两阶段微调：

1. 冻结视频骨干，只训练最终分类层。
2. 当独立验证集可用时，使用验证信号选择 checkpoint，再仅解冻最后一个骨干阶段，以更小学习率
   继续微调。

继续保留类别加权损失，并增加轻量空间裁剪、亮度和时间抖动；增强不得改变动作语义或把对方半场
引入我方裁剪。训练报告必须记录冻结范围、每阶段学习率、增强配置、随机种子和累计标注轮次。

在尚无独立验证比赛标签时，可以按预先固定的训练轮数生成 checkpoint 供下一轮选样，但只能报告
训练诊断；不能使用训练集 Macro F1 选择最佳模型或宣传泛化成绩。

## 数据隔离与评估

如果 Rangitoto 的人工标签加入训练，Rangitoto 就不能继续作为独立 `val` 或 `test`。
项目继续坚持完整比赛隔离：同一视频不得同时出现在多个数据分区。

推荐数据角色为：

- `train`：美国队对德国队，加上经过主动学习确认的 Rangitoto 短片。
- `val`：从 SoCal Cup 或另一场从未加入训练的完整比赛建立固定人工真值。
- `test`：后续再保留一场从未用于选样、调参或阈值选择的完整比赛。

主动学习批次是偏置样本，不能直接计算总体 Accuracy。评估分为三层：

- 随机候选对照估计候选 Precision。
- 无候选时间块和完整短片穷举用于发现漏报；只看候选无法估计 Recall。
- 独立完整比赛报告 Macro F1、逐类 Precision/Recall/F1、混淆矩阵和每分钟误报数。

只有第三层可以作为模型泛化基线。前两层用于指导下一轮选择和检查候选生成器。

## 产物与边界

实现后，每轮至少包含以下不可覆盖产物：

```text
data/active-learning/<video-id>/round-01-selection.json
data/active-learning/<video-id>/round-01-results.json
data/annotations/action-training-round-01.csv
outputs/active-learning/<video-id>/round-01/review.xlsx
outputs/active-learning/<video-id>/round-01/clips/*.mp4
runs/action-active-round-01/{training_config.json,metrics.json,best.pt}
```

选择规格保存候选来源和哈希；人工结果保存来源快照与相对时间；累计清单保存绝对时间和训练分区；
训练目录保存精确模型配置。代理短片是人工便利产物，不是标注真值，允许从选择规格和原视频重建。

建议新增独立的主动学习模块和命令边界：

- `select-review-batch`：验证候选工件并生成确定性选择规格。
- `build-review-batch`：生成 40 个代理短片和精简工作簿。
- `apply-active-review`：校验人工结果并生成新的累计训练清单。

这些命令复用现有 manifest、时间码、视频采样和双裁剪验证模块，不修改全量审计工件。

## 错误处理

- 候选 JSON 或来源哈希不匹配时停止，不生成部分批次。
- 选择输出、人工结果、累计清单或训练目录已经存在时拒绝覆盖。
- 短片缺失、重复、越界或超过允许时长时，在生成工作簿前失败。
- 人工结果缺少任一短片、动作非法、相对时间越界或结束不晚于开始时，拒绝应用整批结果。
- 配额不足时只允许按规定转移并记录原因，不能静默降低批次覆盖。
- 独立验证集不存在时，训练报告显式标记 `generalization_metrics_available: false`。

## 测试与验收

- 固定夹具验证五个选择桶、优先级排他、配额转移、时间分层和固定种子可复现。
- 验证同一候选、来源事件、duplicate group 和 conflict group 不会被重复选入。
- 验证相邻候选合并为一次播放，并满足短片时长与视频边界约束。
- 验证 40 个短片全部有人工动作或显式 `background` 后才能应用。
- 验证相对秒到绝对秒的换算、秒级精度、动作保护区和背景抽样上限。
- 验证来源清单、选择规格和人工结果均不可被输出覆盖。
- 验证同一视频不能跨 train/val/test，主动学习批次不能冒充独立评估。
- 验证训练配置记录冻结阶段、增强、随机种子和主动学习轮次。
- README 与命令、目录、人工工作量、评估限制和当前进度一致。

首轮验收的人工表面为恰好 40 个短片，而不是 2,942 行；用户完成后，程序可以生成新的累计训练
清单和下一轮 checkpoint。模型精度仍需另一个完整比赛的固定真值才能正式报告。
