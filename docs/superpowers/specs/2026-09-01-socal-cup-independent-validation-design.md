# SoCal Cup 独立验证集设计

**状态：** 已确认设计

**确认日期：** 2026-09-01

## 1. 目标

把文件夹中的 SoCal Cup 完整比赛建立为 Spike-Trace 的第一场独立完整比赛验证集，
用它测量当前动作模型在一场未参与训练、选样、推理或人工标注的真实比赛上的表现。
本设计只验证七类动作模型，不开始球员号码归属、数据库、前端或正式技术统计。

## 2. 已确认的数据边界

验证视频固定为：

```text
data/SoCal Cup Final_ MVVC 17 Red vs C2 Attack 17-1, 06_15_2025 [9ESOXojmAGI].mp4
```

冻结的来源信息：

| 项目 | 值 |
| --- | --- |
| 比赛 ID | `socal-cup-final-2025` |
| 我方球队 | `C2 Attack 17-1 Elite` |
| 对手 | `MVVC 17 Red` |
| SHA-256 | `b29e55cde114f5fda745349f86cc878d8abb81ba44ee430f467885bd7ce11c17` |
| 分辨率 | `1920×1080` |
| 帧率 | `60 FPS` |
| 帧数 | `294604` |
| 时长 | `4910.066666666667` 秒 |

SoCal 只写入独立的 `val` 真值文件，不写入当前训练清单、Rangitoto 主动学习批次、
伪标签输入或模型训练缓存。Rangitoto 保持训练用途，不能因为 SoCal 验证而重新划分。
视频文件、比赛 ID 和 SHA-256 在第一次生成验证数据时冻结；源文件发生变化就创建新版本，
不覆盖旧真值。

## 3. 范围与非目标

### 本阶段包含

- 覆盖整场比赛中所有可识别的 C2 比赛回合。
- 记录每局、换边、C2 所在半场和回合边界。
- 逐回合记录 C2 的全部动作，包括没有动作的回合。
- 生成与现有七类模型兼容的验证清单。
- 对当前 checkpoint 运行整场推理并生成事件级、窗口级和可见性指标。
- 保存视频、模型、真值、参数和代码版本，保证结果可复现。

### 本阶段不包含

- 球员检测、跟踪、号码 OCR 或球员统计。
- 依靠模型预测自动生成真值或伪标签。
- 把 SoCal 的任何窗口追加到训练 manifest。
- 把一场比赛的不同局拆成不同比赛或不同数据集来源。
- 根据裁判手势、比分牌或上下文猜测被遮挡动作。
- 把验证结果称为最终产品测试准确率；最终 `test` 仍需另一场从未调参的比赛。

## 4. 总体数据流

```text
SoCal 原视频
  → 元数据与 SHA-256 冻结
  → 初步回合分段
  → 人工修正回合边界和半场映射
  → 不显示预测的逐回合真值标注
  → 真值版本锁定
  → 当前 checkpoint 整场双半场推理
  → 一对一事件匹配
  → 指标、混淆矩阵和可见性报告
```

模型预测只在真值锁定之后出现。这样可以避免模型的错误候选影响人工判断，尤其避免把
模型没有提出的动作误认为不存在。

## 5. 回合分段与覆盖

### 5.1 初步分段

程序先根据连续画面、死球停顿、球员重新站位、比分牌变化和动作间隔产生候选回合。
比分牌只作为辅助信号，不能单独决定边界；当前版本不要求比分牌 OCR 完全可靠。
每个候选回合保存：

- `set_index` 和稳定的 `rally_id`；
- 原视频绝对起止秒数；
- 播放短片的前后缓冲秒数；
- 生成时使用的分段规则和程序版本；
- 初步边界的来源和置信度。

回合片段必须包含发球前准备、完整连续球和回合结束后的短暂缓冲。不得在主要动作中间
强制截断；如果自动边界不可靠，片段宁可稍长，之后由人工缩短。

### 5.2 人工边界确认

用户逐段播放候选回合，只需修正开始和结束秒数、局次和 C2 所在半场。修正发生在真值
锁定之前，且所有修正保留原始边界快照。每个最终回合必须落入以下一种状态：

- `rally`：包含一段完整连续球；
- `non_rally`：暂停、换局、庆祝、场地切换或其他非比赛画面；
- `unusable`：视频本身无法判断，需从可见性指标中排除并保留原因。

最终覆盖记录必须能解释整段视频：比赛回合、明确的非比赛区间和不可用区间之间不能有未覆盖
的空洞。回合覆盖率只有在所有比赛回合都经过“已检查 C2 全部动作”的确认后才达到 100%。
覆盖信息存放在 JSON 中，不在动作 CSV 中新增审核状态、复选框或状态栏。

### 5.3 半场与换边

C2 的 `far` / `near` 不是全场固定值。每局及第五局换边前后分别保存半场映射、有效时间
范围和裁剪坐标；局间空档不继承上一段裁剪。推理时按这些区间分别扫描并合并回原视频时间，
不把不同半场误认为不同球队。

## 6. 真值标注规则

### 6.1 每回合的人工任务

真值界面只显示视频和时间工具，不显示模型动作、置信度或候选排序。用户对每个 `rally`
回合完成以下二选一：

1. 列出该回合中 C2 的全部动作；或
2. 明确记录“本回合没有可标注的 C2 动作”。

不允许把空白动作列表解释为尚未检查。没有 C2 动作的回合在覆盖 JSON 中有明确的完成记录，
在动作 CSV 中不虚构一条动作；评估器从这些已完成的回合覆盖区间推导背景参考窗口，
而不是把“没有 CSV 行”当作背景。

### 6.2 动作标签

使用现有七类动作模型标签：

`background`、`serve`、`receive`、`set`、`attack`、`block`、`dig`。

人工证据层另外允许 `free_ball`，但它不是第八个模型类别：可见 `free_ball` 在模型评估
投影为 `background`，原始标签和备注仍保存在验证 JSON 中。

- `receive`：C2 对对方发球的第一次触球。
- `dig`：针对对方进攻的防守起球，不包括拦网。
- `attack`：扣球、吊球等主动进攻击球。
- `block`：拦网准备、起跳和落地形成的拦网动作；是否有触球另存证据。
- `free_ball`：非进攻的被动送球，不改写为 `attack`。
- 对手失误且 C2 没有触球，不生成 C2 动作。

### 6.3 时间精度与不可见证据

用户继续只需确认到整秒。每条动作同时保存原视频绝对时间、回合内相对时间和标注备注。
对完全遮挡、镜头外或无法确认的情况保存 `fully_occluded`、`off_camera` 或 `unresolved`
证据和时间范围；这些记录用于覆盖统计，但不进入可见动作 Precision、Recall 或 F1 的真值
正样本，也不被当成背景负样本。

### 6.4 验证文件

标准验证 manifest 与详细证据分离：

```text
data/validation/socal_cup_c2_validation.csv
data/validation/socal_cup_c2_validation.json
```

CSV 保持现有清单的兼容字段：

```text
video_path,start_seconds,end_seconds,label,team_side,player_number,
crop_x1,crop_y1,crop_x2,crop_y2,split,match_id,rally_id
```

所有动作行的 `split` 都是 `val`，`match_id` 都是 `socal-cup-final-2025`，
`player_number` 保持为空。`rally_id` 和 `match_id` 是数据谱系字段，不是审核状态字段。
为兼容现有七类 manifest，原始 `free_ball` 行在 CSV 的 `label` 中投影为 `background`；
JSON 同时保留权威原始标签 `free_ball` 和投影理由。CSV 不包含模型预测、置信度、复核复选框
或单独的 `free_ball` 栏目。

JSON 保存完整真值与审计信息：

- 视频绑定、模型无关的元数据和源 SHA-256；
- 局次、换边、半场裁剪和回合覆盖记录；
- 每条动作的原始标签、训练投影、相对/绝对时间、可见性、证据来源和备注；
- 无动作回合、非比赛区间、遮挡区间、镜头外区间和不可用原因；
- 标注版本、创建时间、代码提交 SHA 和人工确认记录；
- 真值锁定后的不可变内容 SHA-256。

## 7. 基线推理与评估

### 7.1 基线模型

第一轮使用当前 bootstrap checkpoint：

```text
runs/rangitoto-r3d18-bootstrap/best.pt
```

运行开始前冻结 checkpoint SHA、模型版本、采样合同、窗口长度、步长、置信度阈值、合并
间隔、最短事件时长、设备和每局裁剪区间。第一次基线使用预先登记的固定参数；如果之后
用 SoCal 选择阈值或 checkpoint，必须把选择过程写入报告，并明确这是 `val` 调参，不是最终
测试成绩。

### 7.2 事件级匹配

模型事件与人工可见动作进行一对一匹配：

- 类别必须相同；`free_ball` 真值按 `background` 投影；
- 预测事件中心与人工动作中心相差不超过 `1.0` 秒；
- 一个预测不能匹配多个真值，一个真值不能匹配多个预测；
- 匹配算法先最大化匹配数量，再最小化总中心时间误差，最后按置信度和稳定事件 ID
  进行确定性排序。

未匹配预测计为误报，未匹配的可见人工动作计为漏报。遮挡、镜头外和未解决动作不计入
可见事件分母，但仍出现在覆盖和不可见报告中。

### 7.3 报告指标

主要事件级报告包括：

- `serve`、`receive`、`set`、`attack`、`block`、`dig` 各自的 Precision、Recall、F1；
- 总支持数、Macro F1 和事件匹配数量；
- 事件级混淆矩阵及 `attack ↔ block`、`receive ↔ set` 的混淆明细；
- 每分钟误报数和按局次分组的误报/漏报。

辅助窗口级报告将覆盖比赛回合按 1 秒时间片展开，比较七类投影标签，输出窗口级 Precision、
Recall、F1、Macro F1 和混淆矩阵。窗口级结果只用于定位边界和类别混淆，不替代事件级指标。
没有 C2 动作的已覆盖回合会由覆盖 JSON 生成背景参考窗口；暂停、庆祝和 `unusable` 区间
不会被误当作背景动作。模型在非比赛区间产生的事件单独计入非比赛误报，不混入可见动作分母。

可见性与覆盖报告包括：

- 回合覆盖率和已完成全动作检查的回合数；
- 可见动作支持数、无候选漏报数、匹配漏报数和误报数；
- 完全遮挡、镜头外、未解决区间的次数、秒数和占全部比赛回合的比例；
- 每局和每个半场裁剪区间的独立统计。

### 7.4 输出目录

第一次基线输出到独立目录，不覆盖训练或 Rangitoto 产物：

```text
outputs/validation/socal-cup-c2-baseline/
├─ metrics.json
├─ confusion_matrix.csv
├─ predicted-events.json
├─ predicted-events.csv
└─ run-manifest.json
```

`run-manifest.json` 绑定验证视频 SHA、真值 SHA、checkpoint SHA、代码提交 SHA 和完整推理
参数。任何后续模型都创建新的版本化目录，并在同一份冻结真值上比较。

## 8. 训练隔离与安全门禁

在生成真值和运行训练前都执行以下检查：

1. 验证视频 SHA 不出现在任何 `train` manifest 或主动学习选择源中。
2. `match_id=socal-cup-final-2025` 只能出现在 `val` 文件；出现 `train` 或 `test` 直接失败。
3. 验证 CSV 的父文件、行顺序、表头和源视频绑定被冻结；手工修改必须产生新版本。
4. 训练命令只接受显式的训练 manifest；验证 JSON、预测事件和评估报告不能被隐式扫描。
5. 不对 SoCal 运行主动学习选择，不把 SoCal 候选、背景窗口或伪标签追加到 Rangitoto 训练。
6. 后续若用 SoCal 选择 checkpoint 或阈值，必须保留选择记录，并禁止把同一结果称为最终
   `test` 准确率。

现有 `load_manifest` 的路径隔离继续保留；实现验证流程时还要增加比赛 ID 和视频内容 SHA
交集检查，防止通过改名、复制或重新编码绕过完整比赛隔离。

## 9. 实施阶段与测试边界

实现按四个可独立验收的阶段进行：

### 阶段 A：视频冻结与回合队列

- 读取并校验视频元数据和 SHA-256；
- 生成候选回合、缓冲短片和局次/半场映射；
- 测试文件变化、时间越界、回合重叠、未覆盖空洞和换边边界。

### 阶段 B：真值标注与锁定

- 提供不显示预测的逐回合标注输入；
- 校验动作时间、标签、半场、可见性和每回合全动作覆盖；
- 生成兼容 CSV 和详细 JSON；
- 测试空动作回合、`free_ball` 投影、不可见区间、重复动作和未确认号码。

### 阶段 C：整场评估器

- 复用现有滑窗推理和半场裁剪能力；
- 实现确定性的一对一事件匹配、窗口级投影和指标计算；
- 测试重复预测、类别冲突、边界容差、遮挡排除和零支持类别。

### 阶段 D：基线运行与文档同步

- 在真值锁定后运行当前 checkpoint；
- 生成完整评估目录和可追溯报告；
- 重新运行训练隔离门禁；
- 每次结构、命令、文件或流程变化同步更新 `README.md` 和 `docs/PROJECT_PLAN.md`。

## 10. 完成标准

本验证任务只有同时满足以下条件才算完成：

- SoCal 源视频 SHA 与冻结值一致；
- 所有比赛回合都有边界和“已检查 C2 全部动作”的覆盖记录；
- 验证 CSV 可被现有 manifest 加载器读取，且所有行均为 `val`；
- 真值锁定前没有模型预测显示，真值锁定后才能生成预测结果；
- 事件级和窗口级指标均能回溯到具体回合和时间；
- 遮挡、镜头外和未解决区间未被当作可见动作正样本或背景负样本；
- 验证视频、真值和预测结果没有进入训练清单或主动学习输入；
- 输出保存视频、真值、模型、参数和代码版本；
- README 与项目计划准确记录当前状态、文件位置和下一步；
- 没有号码归属结果被虚构。

## 11. 后续顺序

1. 完成 SoCal 回合队列和 100% 覆盖真值。
2. 用当前 checkpoint 生成独立 `val` 基线。
3. 根据验证信号决定是否进行两阶段动作模型微调。
4. 微调后在同一 SoCal `val` 比较；另保留一场全新比赛作为最终 `test`。
5. 验证模型稳定后，再实施身份跟踪、号码归属、SQLite 和用户页面。
