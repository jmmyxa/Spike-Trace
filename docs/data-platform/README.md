## 核心结论

1. 采用本地优先的模块化单体，不在首版引入微服务或云端数据库。
2. SQLite 保存结构化事实、版本和谱系；视频、模型、证据片段和导出文件保存在内容寻址的文件资产层。
3. `workspace_id` 是所有业务数据的强制隔离边界。首版允许本机单用户和默认工作区，但数据模型预留成员与角色。
4. 标注、事件修正和统计结果使用不可变版本；当前版本仅是显式指针，不能覆盖历史来源。
5. JSON 是无损交换格式；CSV 是稳定的表格视图。任何导入先验证后提交，任何导出都带契约版本和来源清单。
6. 前端只能通过应用服务/API 访问数据，不能直接读取 SQLite 或任意本地路径。
7. 账户与工作区页面只负责身份偏好、工作区资料、成员占位、存储用量、导入导出与数据维护；全局导航和分析/标注体验不在本 Lane 范围内。

## 推荐方案与备选方案

| 方案 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| 纯版本化 CSV/JSON 目录 | 最贴近当前仓库、可读、易提交 Git | 跨实体查询、事务、去重、权限、统计重算和并发边界薄弱 | 只保留为交换/迁移入口 |
| SQLite + 内容寻址文件资产 | 本地部署简单，有事务、外键、索引和可迁移 schema，同时不把大文件塞进数据库 | 需要迁移层、仓储接口和对象垃圾回收 | 推荐 |
| Postgres + 对象存储服务 | 多用户协作和远程访问能力强 | 部署、认证、运维和网络依赖明显超出当前 MVP | 后续云协作阶段再评估 |

## 第一阶段验收

- 审计覆盖当前标注、复核、补标、模型训练、预训练评估和推理产物。
- 数据模型能表达比赛、视频、标注版本、模型评估、球员归属和可重算统计。
- 版本策略能保留原始预测、人工修正、来源哈希和契约版本。
- CSV/JSON 契约定义编码、字段、校验、事务、冲突和错误报告。
- 存储和 API 边界不要求修改现有事件输出契约。
- 账户/工作区页面边界不侵入产品 Lane 的全局导航和分析/标注体验。
