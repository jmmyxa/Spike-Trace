# Player Identity And Jersey Number Audit

Audit date: 2026-08-10

Scope: current action labels, confirmed USA side segments and crops, video metadata, event outputs, and the evaluation boundary for future player identity and jersey number recognition.

## Verified Repository State

### Existing action and event contracts

- `src/spiketrace/domain.py`
  - `AnnotationRecord` already carries optional `team_side`, `player_number`, and crop fields.
  - `ActionEvent` already carries optional `team_side` and `player_number`.
- `src/spiketrace/events.py`
  - Event IDs are generated per run as `evt_000001`, `evt_000002`, and so on.
  - The current implementation always writes `team_side=None` and `player_number=None`.
- `src/spiketrace/outputs.py`
  - `events.json` and `events.csv` already expose `team_side` and `player_number`.
  - There is no identity evidence, track history, OCR status, or review record in the current output schema.

Implication: the repository already has reserved action-level fields for team side and jersey number, but it does not yet have a contract for detection boxes, tracks, evidence frames, candidate numbers, or human-reviewed identity decisions.

### Current evaluation boundary

- `src/spiketrace/metrics.py` reports classification accuracy, macro F1, per-class metrics, and confusion matrices.
- `src/spiketrace/pretrained.py` evaluates window-level action predictions on manifest windows.
- `src/spiketrace/review.py` supports action review operations such as `keep`, `relabel`, `move_window`, and `add_window`.

There is no built-in metric or truth contract for:

- player detection precision or recall
- track continuity or ID switches
- team identity accuracy
- jersey number OCR accuracy
- action-to-player assignment accuracy
- human review acceptance or override statistics

Implication: identity recognition needs its own evaluation package and should not reuse action metrics as a proxy.

## Audit Findings

### 1. The current action schema is not sufficient for identity evidence

Current action events can hold only a nullable `team_side` and `player_number`. They cannot express:

- per-frame detection boxes
- short-lived track IDs
- identity candidates
- OCR evidence frames
- view state such as front/back/occluded
- review status and reviewer override
- stable cross-run identity references

### 2. USA half-court cropping is not the same thing as USA identity

The confirmed `usa_side_segments` are essential for search scope and throughput, but they can still include opponent players, especially during blocks, attacks, and net-front overlap. Any downstream design that treats the crop as identity truth will inflate false positives.

### 3. Current event IDs are not stable enough to become identity primary keys

`event_id` is generated per output run in `src/spiketrace/events.py`. It is appropriate as a run-local action reference, but it is not a durable primary key for player identity history across reruns. Any future identity result must preserve the original event ID while also carrying a traceable run or snapshot key.

### 4. The repository has no ground-truth set for OCR or tracking

The 90-window manifest is same-match `train` data only. It does not distinguish:

- readable versus unreadable jersey frames
- visible versus occluded player states
- track-level identity truth
- independent validation matches

Without a dedicated identity annotation set, any number-recognition claim would be anecdotal rather than measurable.

### 5. Current review tooling is action-centric

The review pipeline is designed around action label correction, not per-player identity review. Human review for identity will need separate payloads and immutable review records rather than direct edits to action labels.

## Design Constraints Derived From The Audit

- The identity layer must be a sidecar consumer of action outputs, not a rewrite of the action model.
- Detection boxes, `track_id`, `identity_ref`, and jersey number must be stored as distinct concepts.
- Unknown, occluded, unreadable, or conflicting cases must stay unresolved instead of being guessed.
- The stats layer must only consume confirmed identity outputs.
- Identity metrics must be reported on a separate, match-isolated annotation set.
- Half-court crops and segment boundaries must be carried through as priors with provenance, not converted into hard truth.

## Recommended Next-Step Design Direction

Phase 1 should stop at design and documentation. The implementation phase should later add a separate identity contract under `src/spiketrace/identity/` and `tests/identity/`, leaving the shared action runtime unchanged until product decisions are confirmed.
