# Player Identity MVP Runtime

The first runtime slice lives in `src/spiketrace/identity/` and is a sidecar
to the action model. It provides immutable primitives for detector observations
(`PlayerDetection`), short-lived frame tracks (`Track`), OCR observations and
temporal resolution (`NumberObservation`, `NumberResolution`), and the final
track-to-player contract (`IdentityAssignment`).

`court_side` (`near`, `far`, `unknown`) records where a player appears in the
camera view. `team` (`usa`, `opponent`, `unknown`, `out_of_scope`) is kept as a
separate classification so a crop prior cannot silently become team truth.

`aggregate_number_candidates` normalizes digits across OCR frames, optionally
filters against the supplied roster, and returns `confirmed` only when the
weighted winner clears the confidence threshold and the margin over competing
candidates. Missing, occluded, or conflicting evidence remains `not_visible`,
`unreadable`, or `candidate`; no number is guessed.

`apply_identity_assignments` joins only overlapping, confirmed USA assignments
to existing `ActionEvent` objects. It preserves action fields and writes the
camera `court_side` into the existing event `team_side` field and the resolved
number into `player_number`. Unresolved, opponent, and non-overlapping tracks
leave the event unchanged. This adapter is intentionally conservative until a
primary-actor policy is defined.

The MVP does not run a detector, tracker, or OCR engine and does not download
model weights. Those engines can implement these contracts later without
changing the action model or SoCal truth files.
